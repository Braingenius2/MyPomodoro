Drills

Six predictions. Then look.

Predictions correct: 0 of 6

Completeness

1. Loans whose GL code is not on the GL

Risk: a loan is in the subledger and not in the ledger, so loans and advances may be incomplete in the financial statements. An inner join hides this. Use an anti-join.

Duplicates

2. The same account twice

Risk: summing the raw extract double-counts a loan. Deduplicate on the business key before you tie to a control total. Here the duplicated amount is identical, so a careless sum is quietly wrong by 1,500,000.

Accuracy

3. Deduped subledger versus GL

Risk: the population ties in count and still fails in amount. Drop the duplicate first, sum principal by gl_code, then compare to the GL balance. Outer join, so missing codes stay visible.

Count a code if the deduped principal does not equal the GL balance, including codes that exist on only one side.

Accuracy

4. The overdraft difference

One matched code is simply the wrong amount. State the difference as subledger minus GL, after deduping.

Access

5. Privileged access exceptions

Rule, stated so you do not argue with the date: privileged roles are System admin and Finance poster. Flag a user if the role is privileged and either they are inactive or their last login is before 9 July 2026 (90 days before 7 October 2026). Read-only stale access is not in this exception. It may still be a housekeeping issue. It is not this test.

Segregation of duties

6. Preparer approves their own journal

Risk: a manual journal reaches the ledger without an independent review. This is a close-process control. The system should prevent it. If it does not, the detective control is the query you are about to write.
